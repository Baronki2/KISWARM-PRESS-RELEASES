## SSH key rotation procedure (if a key is compromised)
1. Generate new keypair: ssh-keygen -t ed25519 -f ~/.ssh/kiswarm-router-admin-new -C 'opencode-router-admin-v2'
2. Copy new pubkey to vault
3. SSH to router (using still-working old key): ssh root@<router-ip>
4. Append new pubkey: echo '<new-pubkey> opencode-router-admin-v2' >> /etc/dropbear/authorized_keys
5. Test new key works: ssh -i ~/.ssh/kiswarm-router-admin-new root@<router-ip> 'echo ok'
6. Remove old key: ssh root@<router-ip> 'vi /etc/dropbear/authorized_keys' (delete old line)
7. Re-pull authorized_keys and update this file
8. Restart dropbear: ssh root@<router-ip> '/etc/init.d/dropbear restart'

## Forensic checklist for any new router (read-only)
1. SSH with password from vault → cat /etc/dropbear/authorized_keys → save to this file
2. stat /etc/dropbear/authorized_keys → note mtime (when was last key installed)
3. cat /etc/openwrt_release + uname -a + uptime → confirm firmware + boot time
4. uci show dropbear → confirm PasswordAuth, RootPasswordAuth settings
5. logread | grep -E 'auth succeeded|auth fail|denied' → recent SSH attempts
6. ls -la /etc/config/ → uci export dir, look for suspicious config additions
7. ls -la /etc/init.d/ → non-vendor init scripts (especially picea-* / kiswarm-*)
8. find / -newer /etc/dropbear/authorized_keys -type f 2>/dev/null → files modified since last key install
9. find / -mtime -10 -type f 2>/dev/null → recent file activity (catches anything newer than 10 days)
